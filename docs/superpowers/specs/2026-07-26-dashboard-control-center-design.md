# Dashboard Control Center Design

## Goal

Сделать вкладку «Главная» рабочим центром для пяти аккаунтов: быстрые операционные действия, режим каждого аккаунта, последние комментарии и ошибки без обязательного перехода по вкладкам.

## Design

### Dashboard layout

Главная сохраняет текущие метрики, карточки аккаунтов и логи. Между метриками и текущей сеткой добавляется блок быстрых действий: запустить доступные аккаунты, остановить работающие, глобальная пауза, обновить данные, запустить поиск каналов, очистить статистику и сбросить рабочие состояния. Массовые действия пропускают аккаунты со статусами `banned`, `deactivated` и `frozen`; опасные сбросы требуют явного подтверждения.

В сетку добавляются два компактных блока: последние комментарии (до 10 записей, ссылка на Telegram и переход к полному списку) и ошибки/критические события (до 20 записей, переход к логам с фильтром).

### Per-account mode

В таблице/карточке каждого аккаунта появляется select с режимами `Наследовать общий`, `powerful`, `neutral`, `chill`. Для сохранения используется отдельное поле аккаунта `work_mode_override`, допускающее `NULL`. Воркер выбирает override, если он задан, иначе сохраняет существующую глобальную логику `work_mode` и авто-ночной режим. Значение читается во время рабочего цикла, поэтому смена режима не требует перезапуска.

### API and safety

Добавляется `PATCH /accounts/{account_id}/mode` с валидацией только допустимых значений и проверкой существования аккаунта. Обновление атомарно и возвращает сохранённый режим. Существующие `/settings`, старт/стоп и прочие маршруты не меняются.

Ошибки загрузки отдельных блоков не ломают главную: каждый блок показывает собственное сообщение, остальные данные продолжают обновляться. После действий dashboard перезагружается единым refresh-проходом.

## Testing

- Python API/DB tests проверяют миграцию, валидацию режима, сохранение `NULL`/override и выбор режима воркером.
- Статические tests проверяют обязательные dashboard IDs, endpoint вызовы, recent comments/errors rendering и массовые действия.
- `node --check static/app.js`, compileall, полный unittest discovery и `git diff --check` остаются обязательными.
