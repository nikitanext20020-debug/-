# Account Join Modes Design

## Goal

Добавить управляемый per-account режим вступления в каналы, чтобы очередь из десятков каналов обрабатывалась постепенно и не останавливала нейрокомментинг.

## Modes

- `off` — автоматические вступления отключены.
- `new` — задержка 120–180 секунд между попытками.
- `careful` — задержка 60–120 секунд.
- `normal` — задержка 30–60 секунд.

Новые добавленные аккаунты получают `new`. Существующие аккаунты после миграции получают `normal`.

## Architecture

В таблицу `accounts` добавляются `join_mode` и `next_join_at`. `next_join_at` хранится как Unix timestamp и поэтому переживает перезапуск процесса. Worker запускает отдельный фоновый scheduler: он ждёт персональный таймер, выполняет максимум одну попытку вступления, назначает следующий случайный интервал и снова ждёт. Ожидание происходит в отдельной coroutine и не блокирует основной цикл комментариев.

Дублирующие автоматические пути `_join_pending_channels` и `_gradual_join_from_database` заменяются одной операцией `_join_next_channel`, которая использует существующие DB-фильтры, блокировки, `ChannelJoiner`, pending-заявки и account-local статусы.

## API and dashboard

`PATCH /accounts/{account_id}/join-mode` принимает `off`, `new`, `careful` или `normal`. При смене режима сервер сразу назначает новый `next_join_at`; `off` очищает таймер. `/accounts` возвращает режим, границы задержки и оставшиеся секунды.

На главной в каждой карточке аккаунта рядом с режимом комментинга появляется select «Вступления» и обратный отсчёт до следующей попытки.

`POST /discovery/channels/join-private` больше не выполняет длинную блокирующую операцию и не включает глобальную паузу. Он активирует ближайший персональный слот работающих аккаунтов, после чего обычные scheduler-ы продолжают разбирать очередь. Выбор аккаунтов остаётся независимым: FloodWait или `frozen_join` одного аккаунта не останавливает другие.

## Safety

- `banned`, `deactivated`, `frozen` и `frozen_join` не выполняют автоматические вступления.
- DB/health pause и Telegram FloodWait имеют приоритет над join mode.
- Один worker не может выполнять две join-попытки одновременно.
- Канал освобождается из shared lock после каждой попытки, поэтому остальные аккаунты не блокируются на час.
- Неиспользуемые `JOIN_CHANNEL_DELAY_MIN/MAX` удаляются.

## Verification

Тесты покрывают миграцию, defaults для новых/существующих аккаунтов, API-валидацию, диапазоны таймеров, scheduler gating, отсутствие старых блокирующих join-вызовов, неблокирующий bulk endpoint и dashboard hooks.
